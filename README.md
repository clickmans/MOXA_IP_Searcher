# MOXA 设备 IP 搜索工具

一个 **Windows 64 位、单文件、零依赖** 的 MOXA 全产品 IP 广播搜索工具。
双击 `dist\MOXA_IP_Searcher.exe` 即可运行，无需安装、无需 .NET / VC 运行库 / Python。

---

## 1. 使用说明

### 1.1 图形界面

双击 `MOXA_IP_Searcher.exe`：

1. 内容区**左上角**是 **「广播搜索」** 按钮，按钮下方是结果表格，底部是状态栏
   （`就绪 · 4 张网卡`）。本机所有已启用网卡的完整清单（含 IP/掩码/网卡名）
   **鼠标悬停状态栏**即可看到 tooltip，不再占用主界面顶部一行。
2. 点击 **「广播搜索」**——**不会弹出任何确认框**，立即出现进度窗口。
3. 进度窗口正文只有**一行状态信息**（`正在准备广播…` → `第 N/3 轮 · 已发现 M 台设备`），
   下方是进度条（0% 时也有灰色底槽，一眼能看出是进度条）；标题「正在搜索 MOXA 设备…」
   只出现在标题栏，正文不再重复。搜索结束**自动关闭**。
   它是主窗口的**附属窗口（owned window）**，只在主窗口之上，**不会置顶遮挡其他软件**。
4. 主窗口表格显示结果，状态栏给出汇总，例如
   `搜索到 4 台设备 · 耗时 1659 ms`。

> 状态栏的单位是「台」：**N = 按 MAC 去重后的设备数**，不是行数。一行 = 一个 IP，
> 一台设备配了多个地址会占多行，所以按行数报会把一台设备说成两台。
> 若多台设备共用一个 IP，会追加 `（M 台设备 IP 重复）`。没有 MAC 的行各自计 1 台。

列表列（v1.1，顺序固定）：

```
序号 | 产品型号 | IP 地址 | MAC 地址 | 固件版本号 | 设备名称 | 设备信息来源网卡
```

- **产品型号**：`0x03` 的 Model → 空则用设备名称推导（`NP6450_5599` → `NPort 6450`、
  `MG-MB3180_579` → `MGate MB3180`，其它前缀如 `EDS-`/`EOM-`/`IA-` 原样返回）→ 仍为空显示 `-`；
  **设备名称**：与型号列相同时显示 `-`，避免同一串文字显示两遍。
- **固件版本号**：AXOM（40404）的 TLV `0x36001000` 与 4800 的 `0x16` 查询结果，其余显示 `-`。
- 「协议」列不再显示（JSON 里仍保留 `protocol` 字段，供排障使用）。
- 列宽按内容自适应；内容总宽超过窗口时出现**横向滚动条**，不会把文字截断。
- 字号 14（`fontPointSize`，96 DPI 下的像素高，约 10.5 pt），行高/表头/按钮/状态栏高度都随字号自适应。
- **Ctrl+C** 复制选中行（TSV，可直接粘贴到 Excel）。
- **双击行** 用默认浏览器打开该设备的 WEB 管理界面（v1.4）：
  - 先探测设备的 80 / 443 端口（各 500 ms，并行，不阻塞界面），**80 能连就用 `http://`**（MOXA 设备在 80 上直接给登录页，且避免 443 自签名证书的警告），只有 80 不通才用 `https://`；
  - 两个端口都不通时仍按 `http://` 打开，但状态栏会写明「80/443 未响应，浏览器可能无法打开」；
  - 结果只写状态栏（`正在打开 …` → `已在浏览器中打开 http://…`），**不弹任何窗口**；
  - 同一 IP 上有多台设备时，状态栏提示「该 IP 上有 N 台设备，浏览器访问的是 ARP 命中的那一台」——浏览器按 IP 访问，无法像本工具那样按 MAC 区分。
- 搜索期间界面不会卡死（搜索在后台线程执行，可拖动、可重绘）。
- 所有错误信息只写状态栏，程序**任何情况下都不弹 MessageBox**。

#### LLDP 邻居面板（v1.8）

设备表格下方是一块**常驻面板**（不做 tab 切换，设备列表仍至少能显示 6 行；上下占比可用鼠标拖动，见下一节）：

- 顶部一行概要，按状态显示：
  `选中上方一台设备可查看它的 LLDP 邻居` → `正在读取 192.168.127.4 的 LLDP 邻居…` →
  `机箱 ID：0090e80005d0　系统名：Managed Redundant Switch 00007　描述：EOM-106`；
  读到了但没有邻居时在后面补 `　· 该设备没有 LLDP 邻居`（行数本身已由下方表格直观体现）；
  设备没有 SNMP 代理时显示 `该设备未响应 SNMP（community=public），无法读取 LLDP`。
  若该 IP 上有多台设备（IP 冲突），概要在后面补
  `　（该 IP 上有 N 台设备，读取的是 ARP 命中的那一台）`——SNMP 按 IP 走，只能读到 ARP 命中的那台。
- 下方表格列：`端口 | 邻居 ID | 邻居端口 | 描述 | 系统名`，整行选中 + 网格线。
  列宽按内容自适应，**内容超宽时等比压缩列宽**（不出现横向滚动条——横向滚动条会吃掉一行高度，
  让“最小两行”变成 1.5 行，见 v1.9）。
  「端口」是**被查询设备自己的端口号**（LLDP 索引的第 2 段），不是对端端口。
- 触发方式：**选中设备行**即读取（`LVN_ITEMCHANGED`）。同一行重复通知不会重复读取；
  正在读 A 时又选中 A 会忽略；读取在后台 goroutine 中完成，结果 `PostMessage` 回主线程
  （`WndProc` 内绝不做网络 IO），切换设备时旧结果按 generation 丢弃，不会串行；
  搜索进行中选中行不触发读取。
  一次真实点击会同步产生两条通知（旧行取消选中、新行选中），所以通知处理**只排一条
  `WM_APP+6`**，在消息队列下一轮才读当前选区——两次通知因此合并成一次判断，
  对同一行连点 N 次只会读 1 次（实测 10 次点击 = 0 次额外读取）。
- 传输：**SNMPv2c，community `public`，UDP 161**，标准 LLDP MIB `1.0.8802.1.1.2`，
  500 ms × 2 次超时；先用一次 GET `lldpLocChassisId` 探测，设备不应答即判定「无 SNMP」，
  总耗时 ≤ 1.2 s（NPort 6450 实测 1002 ms），不影响发现结果。

#### 拖动分隔条 / 表头排序 / 网卡筛选（v1.9，筛选入口 v1.9.1 起只在表头）

三件事都只影响“怎么显示”，**不改发现结果**：JSON 输出、状态栏的“台数”、Ctrl+C、双击打开、
LLDP 读取的行为与 v1.8 完全一致。

**1）上下占比可拖**（`src/internal/ui/splitter.go`）

- 两个表格之间是一条 10 DIP 高的分隔条（浅灰细线 + 中间深一点的抓手），鼠标移上去变
  **上下箭头光标**，按住拖动即可调整占比；松手前一直跟着指针，拖出条外也不会断。
- 占比以 **1/1000 的比例**保存，改窗口大小或换 DPI 时比例保持不变（不是记死像素）。
- **两道硬闸**：
  - 下方 LLDP 表最小只能到**整两行**（表头 + 2 行完整数据，行高从控件实测、高度按整行吸附，
    所以不会出现“半个第三行”的错位，也不会有横向滚动条挤掉一行）；
  - 上方设备表最小 6 行（v1.8 的既有约束），再往上拖也不会把设备表压没。
  - 到达闸值后继续朝同一方向拖，界面**完全不动**（请求被钳制，不重排、不重绘）。
- 拖到最小高度时的实测：LLDP 表客户区 = 表头 42 + 2×39 = 120 px（200% DPI），两行完整可见，
  竖滚动条照常出现且不影响行高。

**2）点表头排序**（`src/internal/ui/deviceview.go`）

- 点 **「产品型号」**：按型号升序/降序，**型号相同按 IP 地址，型号与 IP 都相同按 MAC 地址**；
- 点 **「IP 地址」**：按 IP 升序/降序（**按数值**，`…9` 排在 `…10` 前），**IP 相同按产品型号，
  IP 与型号都相同按 MAC 地址**；
- 同一列表头连点切换升降序，换一列则从升序开始；**降序是把整条比较链一起反转**（三级键同时反向）。
- 表头文字直接带箭头：`产品型号 ▲` / `IP 地址 ▼`（不用 `HDF_SORTUP`——本程序无 comctl32 v6
  清单，经典表头根本不画排序箭头，会静默失效）。
- 未识别型号（`-`）在按型号排序时**始终排最后**（升序降序都一样），因为它不是型号。
- 排序对**全部搜索结果**生效（先筛选再排序，序号 1…n 重排），且**保留当前选中行**：
  按设备身份（MAC+IP）找回它，LLDP 面板不重读、不闪回“未选中”文案。
- 其余列（序号 / MAC / 固件 / 设备名称）点表头不做排序。

**3）按「设备信息来源网卡」多选筛选**

- 入口只有一个（v1.9.1 去掉了独立的「网卡筛选」按钮）：**点「设备信息来源网卡」表头**，
  菜单在该列下方、指针处弹出——这一列本身就是筛选键，不必另占按钮位。
- 菜单是**可勾选列表**：全部网卡默认勾选 = 显示全部；取消勾选某张网卡即隐藏来自它的设备；
  多张同时勾选即“只显示这几张网卡来源的设备”。设备若被两张网卡同时看到（列里是
  `WLAN, 以太网`），只要其中一张在勾选集合里就保留。
- 底部 `显示全部网卡` 一键清除筛选（无筛选时置灰）；**把最后一张也取消**等于清除筛选
  （不会出现空表）。
- 筛选状态只写在**状态栏**：`· 已筛选：显示 7/8 台`（分子分母都按“台”统计）。
- 筛选与排序、占比**互不影响**：筛选后仍可排序（排序对筛选结果生效），再清除筛选时排序保留。
- 新的一次「广播搜索」会把筛选重置为“全部网卡”（网卡清单可能已变）；排序偏好保留。
- 筛选隐藏了当前选中行时，该行被取消选中、LLDP 面板回到提示文案——行确实不在表里了。

### 1.2 无界面模式（自动化回归 / 排障）

```
MOXA_IP_Searcher.exe --scan --out result.json [--timeout 1500]
```

| 参数 | 说明 |
|---|---|
| `--scan` | 执行一次完整搜索，不创建窗口 |
| `--out` | JSON 输出路径；留空则写到标准输出 |
| `--timeout` | 搜索总时长（毫秒），默认 1500；广播轮次与单次详情查询超时（钳制在 300–400 ms）按此预算分配，实际耗时 ≈ 轮次 + 3 次详情查询 |
| `--lldp <ip>` | （v1.8）读取该设备的 LLDP 邻居表并打印为文本，排障用；与 `--scan` 互不影响 |

`--lldp` 示例（真实输出，2026-11-03 实测）：

```
> MOXA_IP_Searcher.exe --lldp 192.168.127.4
设备 192.168.127.4
  机箱 ID : 0090e80005d0
  系统名  : Managed Redundant Switch 00007
  描述    : EOM-106
  邻居    : 4 条
  - 端口 2 | 邻居 ID c85b76f2204a | 邻居端口 c85b76f2204a | 描述 - | 系统名 -
  - 端口 3 | 邻居 ID 0090e84cd232 | 邻居端口 3 | 描述 100TX,RJ45. | 系统名 Managed Redundant Switch 01508
  - 端口 4 | 邻居 ID 0090e8d65985 | 邻居端口 7 | 描述 100FX,SC,Single,40. | 系统名 Managed Redundant Switch 49538
  - 端口 5 | 邻居 ID 500b880b6267 | 邻居端口 4 | 描述 100SC,Multi. | 系统名 Managed Redundant Switch 09561

```

退出码：`0` 读到表（含空表），`2` 设备不响应 SNMP，`1` 其它错误。

> ⚠️ **`--lldp` 的输出要从文件取**：exe 是 **GUI 子系统程序**（`-H=windowsgui`），
> 进程没有控制台，PowerShell 里 `& .\MOXA_IP_Searcher.exe --lldp 1.2.3.4` 拿不到 stdout。
> 用重定向文件，或走 `Start-Process -Wait`：
>
> ```powershell
> Start-Process -FilePath .\dist\MOXA_IP_Searcher.exe `
>     -ArgumentList '--lldp','192.168.127.4' `
>     -Wait -NoNewWindow `
>     -RedirectStandardOutput lldp.txt -RedirectStandardError lldp.err
> Get-Content lldp.txt
> ```
>
> 在 Git Bash / cmd 里直接运行不受影响（shell 会把管道作为继承句柄交给 GUI 进程）。
> `--scan --out <文件>` 同样建议写文件而不是依赖标准输出。

退出码恒为 `0`（未发现设备不是错误）。JSON 结构：

```json
{"started_at":"2026-11-02T11:00:00+08:00","elapsed_ms":1523,
 "adapters":[{"name":"WLAN","ip":"192.168.0.163","mask":"255.255.255.0"}],
 "devices":[{"ip":"192.168.127.4","mac":"00:90:E8:00:05:D0","model":"","name":"EOM-106",
             "firmware":"V3.1.10 build 26102915","protocol":"AXOM/40404","adapters":["WLAN"]}],
 "stats":[{"protocol":"WSU/5800","port":5800,"local_port":15802,"adapter":"WLAN",
           "received":2,"decoded":2}],
 "errors":[]}
```

`devices` / `adapters` / `stats` / `errors` 在为空时输出 `[]`（不会是 `null`）。
`stats` 是**诊断计数器**（v1.6 起）：每张网卡 × 每个协议一行，`received` 是收到的字节报文数，
`decoded` 是其中解析成设备的数量。同一台设备在两台电脑上一个有字段一个没有时，先看这里——
`received = 0` 说明回包没到这台机器，`received > 0` 而 `decoded = 0` 说明帧到了但布局不认识。
`firmware` 为 `""` 表示该协议/机型不上报固件版本。`protocol` 字段只出现在 JSON 里
（v1.1 起界面不再有「协议」列）。
`errors` 收集非致命问题（端口被占用、广播发送失败等），不会中断搜索。

## 2. 支持的协议

| 端口 | 协议 | 覆盖产品 | 请求（hex） | 应答解析 |
|---|---|---|---|---|
| **4800** | Moxa Device Discovery | NPort、MGate、CN2600/DSU、部分新交换机 | `0100000800000000` | `0x81` 且长度 ≥ 24：`[14:20]`=MAC，`[20:24]`=IP |
| **4000** | EDS 交换机发现 | EDS / EOM 系列 | `480000062627`（另发伴随帧 `490000062627`） | `0xC9` 且长度 ≥ 24：IP 取 **UDP 源地址**（帧内 `[14:18]` 是请求方地址），`[18:24]`=MAC，`[24:64]`=型号 |
| **40404** | AXOM | WIFI6 / AWK-1161、EDS-G4012、部分 EDS/EOM | 40 字节 `"AXOM"` 头 + nonce，**两种类型都发**（`…01` 给 G4012 类、`…07` 给 WIFI6 类） | `"AXOM"` 头 + TLV 遍历（type BE32 / len LE32，4 字节对齐）；132 B 与 136 B 都能解 |
| **5800** | WSU 无线发现 | AWK-1131A / 1132C / 1137C 等 WIFI4 | 68 字节（内嵌本网卡 MAC/IP/端口） | 魔数高字节 `0x0D`/`0x1D` + 低字节 `0xBD`/`0xBF`，固定偏移 + 扫描兜底（218 / 234 B 均可） |
| 29168 | 同 4800 格式（兜底） | DSU / MXConfigCS | `0100000800000000` | 按已知布局逐个尝试 |
| 1029 | NPort Admin / MXConfigCS（兜底） | — | `020000060000` 与 `490000060000` | 同上 |
| 22222 | EDS 老机型 `"STR_BCAST"`（兜底） | 老 EDS | 28 字节 ASCII | 同上 |

兜底端口未见应答，发送即忘；若意外收到应答，会按已知布局解析，解析不出来时只展示来源 IP。

### 2.1 详情查询：型号 / 名称 / 固件（v1.2）

对每个 4800 应答且带 12 字节设备 ID 的设备，用**发现它的那张网卡**的 socket 依次发 3 个短查询
（超时各 300–400 ms，**设备之间并行**，设备内部串行）：

| 命令 | 请求帧（20 字节） | 应答 | 取值 |
|---|---|---|---|
| `0x03` | `03 00 00 14` + seq(4) + ID(12) | `0x83` | 文本在 `payload[20:]`，搜 `"Model\t"` 到 `\n`（同帧有 `Firmware\t` 也一并取用） |
| `0x10` | `10 00 00 14` + seq(4) + ID(12) | `0x90` | 名称 = `payload[20:]` 起第一个 NUL 结尾的 ASCII 串 |
| `0x16` | `16 00 00 14` + seq(4) + ID(12) | `0x96` | 版本见下 |

**`0x83` 的「拒绝」语义**：NPort 6450 对 `0x03` 回 `83 04 00 14 <seq> <ID12>`（20 字节、
`payload[1] & 0x04`、无数据）。这是**合法应答**，不是解析失败：型号留空，走上表的名称推导回退。

**`0x16` 版本解析**（两台真机交叉验证）：应答 36 字节 =
`96 00 00 24` + seq(4) + ID(12) + tail(16)

| 位置 | 含义 |
|---|---|
| `tail[3]` | 主版本号（十进制） |
| `tail[2]` | 次版本号（**BCD**：`(b>>4)*10 + (b&0x0F)`，所以 `0x10` 是 10 而不是 16） |
| `tail[8:10]` | 短序列号（LE uint16，579 / 5599），本版只解析进结构体备用，不显示 |

格式化 `V%d.%d`：MGate MB3180 `07 02` → `V2.7`（MXConfig 显示 V2.7build25060913 ✓）；
NPort 6450 `10 01` → `V1.10`（DSU 显示 Ver1.10 ✓）。`tail[2]/tail[3]` 为 0 或不是合法 BCD 时视为无效，留空。

帧的投递方式：**单播 + 该网卡的广播各发一份**。单播是快路径（v1.1 起可用，前提是上一节的
`IP_UNICAST_IF`）；广播保留 v1.1 的跨网段能力。设备只应答携带自己 ID 的帧，因此逐设备广播是安全的。

### 2.2 固件版本号

| 协议 | 来源 | 说明 |
|---|---|---|
| **40404 / AXOM** | TLV `0x36001000` | 字符串（现场实测为纯 ASCII，如 `V3.1.10 build 26102915\n`；规范文档描述的 hex 编码 ASCII 也兼容），去尾部 CR/LF/空白；不可打印则留空 |
| **4800** | `0x96` 应答的 `tail[2:4]` | 见 §2.1，格式 `V<主>.<次>` |
| **4000 / 5800** | — | 应答里没有固件字段，恒为 `-` |

AXOM 同帧还会解析 `0x32000001`=序列号、`0x37000001`=设备描述、`0x38000001`=位置，
本版只存进结构体备用，不在界面显示。

## 3. 实现要点

- **逐网卡广播**：`net.Interfaces()` 枚举所有已启用、非 loopback 的 IPv4 网卡，每张网卡对每个协议
  各发两份：受限广播 `255.255.255.255` 与子网定向广播 `(ip & mask) | ~mask`。
- **每网卡独立 socket**：`bind(网卡IPv4, 0)`（5800 用 `15802`，被占用则退化为临时端口并广告该端口），
  开 `SO_BROADCAST` + `SO_REUSEADDR`（在 bind 之前设置，故走 `net.ListenConfig.Control`）。
- **强制出接口（v1.2）**：socket 建好后设 `IP_UNICAST_IF = 网卡索引`（`IPPROTO_IP`, optname **31**，
  值必须是**网络字节序的 4 字节**）。原因：bind 源地址不决定出口，Windows 按**目的地址**查路由——
  现场 `.250` 只挂在 WLAN 侧，而 `192.168.127.0/24` 的路由走以太网，于是"广播能收到、后续单播全丢"，
  型号列空白。设失败不致命（老系统可能不支持），记一条 warning 后继续。
  注意 `syscall.SetsockoptInt` 传的是**主机序**，小端机器上会算成另一个索引号，因此这 4 个字节
  由代码手工按大端编码，直接调 `ws2_32!setsockopt`（`syscall.SetsockoptString` 只在 Unix 端口存在）。
- **回包在同一 socket 上收**：设备把应答发回我们的源端口（`255.255.255.255:<源端口>`），
  绑定具体网卡 IP 的 socket 能收到这些广播回包，无需 `0.0.0.0` 监听。
- **跨网段可发现**：受限广播只在二层传播，因此设备 IP 与本机不同网段（同二层）也能收到。
- **行身份 = (MAC, IPv4)**：
  - 同一个 `(MAC, IP)` 被多协议/多网卡发现 → 合并为一行（协议取优先级最高者
    4800 > 4000 > 40404 > 5800 > 兜底，网卡列合并去重）；
  - **同 IP 不同 MAC → 两行**（R4：多台设备共用同一 IP 时必须全部列出）；
  - **同 MAC 不同 IP → 两行**（一台设备配了多个地址时每个地址都要列出）。
  - MAC 未知时（只有兜底协议收到来源 IP）行身份退化为 `(IP, 协议)`，避免误合并。
- **轮次**：3 轮 × 400 ms（可按 `--timeout` 调整），每轮结束回调一次进度。
- **单文件无依赖**：`CGO_ENABLED=0`，只用标准库（`net` / `syscall` / `unsafe` / `encoding/binary` /
  `encoding/hex` / `encoding/json` / `unicode` …），GUI 直接调 `user32` / `gdi32` / `comctl32` /
  `kernel32`，产物 `-H=windowsgui -s -w`（约 2.7 MB）。
- **图标**：`src\rsrc.syso`（RT_GROUP_ICON id=1）由链接器自动并入 PE，
  主窗口与进度窗口都 `WM_SETICON`（ICON_BIG + ICON_SMALL）。
- **字号与布局**：字体 `Segoe UI`，`fontPointSize = 14`（v1.1 的 18 偏大，现为 96 DPI 下 14 px 高，约 10.5 pt；
  `CreateFontW` 负高度按 DPI 换算）。所有控件高度都由 `GetTextMetrics`（行高）派生，
  列宽由 `GetTextExtentPoint32` 按内容实测，因此改字号不需要改任何像素常量；
  窗口默认 1180×720 DIP，运行时钳制在 `SPI_GETWORKAREA` 内。
- **进度窗口不置顶（v1.1）**：`WS_POPUP | WS_CAPTION` + `WS_EX_TOOLWINDOW`，
  `hWndParent` 传主窗口 ⇒ Windows 的 owned window 语义（只在主窗口之上），**不含 `WS_EX_TOPMOST`**。
- **网卡清单（v1.1）**：主界面不再有网卡行；状态栏显示 `就绪 · N 张网卡`，
  完整清单挂在状态栏的 `tooltips_class32` tooltip 上。
  注意本程序无 manifest ⇒ 加载 comctl32 v5，`TTM_ADDTOOLW` 要求 `TOOLINFO.cbSize` 为 **64**
  （v6 是 72），尺寸不符时该消息**静默失败**，代码对两种尺寸都做了尝试。

## 6. 已知限制

1. **只能发现同一二层广播域内的设备**。跨路由、跨 VLAN 不保证——这与 MOXA 官方工具一致。
2. **官方工具同时运行**：MXConfig / DSU / NPort Administrator / MGAManager 会占用同样的目的端口，
   一般不影响本工具（本工具用临时源端口收包）；若 5800 的本地端口 `15802` 被占用，
   本工具自动退化为临时端口并在报文里广告该端口，同时把情况写进 `errors` / 状态栏。
3. **设备侧关闭了发现服务或被防火墙拦截**时搜不到。
4. **型号列可能为空**：设备对 `0x03` 回 `0x83` + 标志 `0x04`（无数据）或干脆不应答时，
   型号改由**设备名称推导**（`NP6450_5599` → `NPort 6450`），推导不出来才显示 `-`。
   40404（AXOM）应答里只有主机名（TLV `0x34000001`），没有型号字段，因此 AXOM 行的
   「产品型号」列是名称推导的结果（`EDS-408A-SS-SC` 这类前缀原样返回）。
5. **固件版本号可能为空**：4000 / 5800 协议没有固件字段；4800 需要设备支持 `0x16` 查询
   （NPort 6450 → `V1.10`、MGate MB3180 → `V2.7`，均已实测）；AXOM 机型上报
   （本机 EOM-106 为 `V3.1.6` / `V3.1.10`）。空值在界面显示 `-`，JSON 为 `""`，不影响其他列。
6. **DPI**：运行时通过 `SetProcessDpiAwarenessContext(PER_MONITOR_AWARE_V2)` 声明 DPI 感知
   （无内嵌 manifest），窗口尺寸按屏幕 DPI 缩放并**自动钳制到可用桌面区域**（本机
   2560×1600@200% 实测客户区 1180×700 DIP），列宽按内容实测，总宽不够时横向滚动。
   由于没有 manifest，通用控件使用 comctl32 v5 的经典外观（无视觉样式主题）。
7. **不发 ICMP / ARP 扫描**，只发 UDP 广播，不会主动连接设备。

## 7. 故障排查

| 现象 | 处理 |
|---|---|
| 一台都搜不到 | 确认设备和本机在同一交换机/二层域；用 `--scan --out -` 看 `adapters` 是否列出了正确网卡；确认没有 169.254 自动地址 |
| 某类设备搜不到 | 看 JSON 的 `protocol` 字段（界面 v1.1 起不再显示协议列）：串口服务器看 4800，交换机看 4000/40404，WIFI4 看 5800 |
| **同一台设备，这台电脑有型号、那台电脑没有** | 看 `--scan` 输出里的 `stats` 数组（v1.6 起）。按 `port` 找到对应协议，`received = 0` ⇒ 回包**根本没到这台机器**（防火墙、网卡路径、端口被别的程序占着）；`received > 0` 但 `decoded = 0` ⇒ 帧到了但**布局不认识**（未知魔数/新固件）。典型例子：AWK-1137C 的型号只存在于 5800 应答里（它的 4800 不提供型号），所以 `stats` 中 `port=5800` 全为 0 的机器一定看不到 1137C 的型号 |
| 状态栏提示端口绑定失败 | 关闭 MXConfig / DSU 等官方工具后重试 |
| 想抓包自查 | 过滤器：`udp.port in {4800, 4000, 40404, 5800, 29168, 1029, 22222}` |
| 排障要更详细日志 | 设环境变量 `MOXA_DEBUG=1`，收包层与界面层的非致命信息会打到 stderr（默认静默；GUI 版需从命令行重定向 `2> ui.log` 才能看到） |
| 双击打不开设备网页 | ① 状态栏若提示「80/443 未响应」，说明本机到该 IP 没有路由（常见于设备只在**无线那侧**被广播发现、而有线路由把它带向了别的网段）；② 同 IP 多台设备时打开的是 ARP 命中的那一台，想精确访问需先解决 IP 冲突 |
| 想看完整网卡清单 | 鼠标悬停在主窗口状态栏上（tooltip） |

### v1.7（修复 EDS 交换机搜不到：4000 的命令字节与应用层地址）

| 项 | 变更 |
|---|---|
| 根因 1 | 4000 的发现命令写成了 `0x49`，而设备只应答 **`0x48`**。实测同一时刻、同一台 PC、只改这一个字节：`0x49` → **0 台应答**，`0x48` → **5 台应答**（`_analysis/probe_4000_pair.py`）。只应答 4000 的 `192.168.127.1`（EDS-510A-3SFP-2SSC）、`192.168.127.2`（EOM-409-3SSC）因此一直搜不到；`.3/.4/.253` 因同时应答 4800/40404 才没暴露 |

### v1.5（修复 EDS-G4012 搜不到：AXOM 请求有两种类型）

| 项 | 变更 |
|---|---|
| 根因 | EDS-G4012 只应答 AXOM 请求类型 `00 08 01 **01**`，而工具一直只发 `00 08 01 **07**`（WIFI6 那类）。抓包 `mxconfigcs-g4000.pcapng` 显示 MXConfigCS 是**两种都发**；原样重放验证：`…01` 收到 2 次 136 B 应答、`…07` 收到 0 次，其余字节完全相同 |
| 修法 | `buildAXOMRequests` 每张网卡返回 **2 个 40 字节请求**（`…07` 与 `…01`，nonce 相同），发送循环原有逻辑即可覆盖；解析器不变（132 B / 136 B 都能解），重复回包按 `(MAC, IP)` 合并 |
| 影响面 | 仅 40404 多 40 字节/网卡/轮，搜索总耗时不变（实测 1593–1630 ms）；WIFI6 设备行为不变（先发的仍是 `…07`） |
| 实测 | EDS-G4012（`00:90:E8:E5:5C:BF` @192.168.127.253）现在能列出，型号列显示其主机名 `EDS-G4012-4GC`（AXOM 无型号 TLV）；同 IP 的 NPort/AWK 两行不受影响 |
| 已知 | G4012 的应答没有固件 TLV，其 ubus 也不存在（`/ubus` 返回 404）、SNMP 无应答 ⇒ 固件列保持 `-` |

### v1.2（型号/名称/固件补齐 + 字号 14）

| 项 | 变更 |
|---|---|
| socket 出接口 | 每个网卡 socket 建好后设 `IP_UNICAST_IF`（`IPPROTO_IP`, **31**，值 = 网络字节序 4 字节网卡索引，手工大端编码 + `ws2_32!setsockopt`）。修掉「广播能发现、单播查询全丢 → 型号空白」的根因；设置失败只记 warning，不影响广播 |

| 单测 | 88 → 158 例，新增 `0x96` 版本（含 BCD 边界）、`0x83` 拒绝语义、`0x90` 名称、三帧请求布局、名称→型号映射（NP/MG-/EDS/未知）、`IP_UNICAST_IF` 字节序、AXOM 行不受回退影响 |
